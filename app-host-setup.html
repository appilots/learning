เครื่องนี้จะเป็น ที่รวมกลาง สำหรับรันแอปภายในที่เขียนขึ้นเองทั้งหมด (เริ่มจาก ATTG ACM และแอปในอนาคต) โดยใช้ Docker แยกแต่ละแอปเป็นกล่องอิสระ และมี SQL Server Express เป็นฐานข้อมูลกลางของตัวเอง เนื่องจากทั้ง 6 บริษัทในกลุ่ม ATTG เชื่อมเครือข่ายภายในถึงกันอยู่แล้ว เครื่องเดียวนี้จึงให้บริการทุกบริษัทได้โดยไม่ต้องพึ่ง Cloud

  • Static IP Address ที่จะให้เครื่องนี้ใช้ (1 หมายเลข ห้ามซ้ำกับเครื่องอื่น)

01

สร้าง VM บน Nutanix

สเปกเครื่องที่แนะนำ และเหตุผล — SQL Server Express (ฟรี) มีเพดานของตัวเองอยู่แล้วไม่ว่าเครื่องจะแรงแค่ไหน: ใช้ RAM ได้จริงสูงสุด ~1.4 GB ต่อฐานข้อมูล และใช้ CPU ได้สูงสุด 4 core เท่านั้น ส่วน RAM/CPU ที่เหลือของเครื่องจะไปให้ตัว OS + Docker + แอปต่างๆ ที่รันคู่กัน:

attg-apphost-01
!
ขยายได้ทีหลัง — ถ้าเพิ่มแอปมากขึ้นแล้วเครื่องเริ่มช้า ปรับเพิ่ม vCPU/RAM ผ่าน Prism ได้เลยโดยไม่ต้องสร้างใหม่ (แต่ SQL Express เองจะยังใช้ RAM/CPU ได้แค่เพดานเดิม ไม่ว่าจะเพิ่มเครื่องแค่ไหน — ถ้าวันหนึ่งฐานข้อมูลโตเกิน 10GB/ตัว หรือใช้งานหนักมาก ค่อยพิจารณาอัปเกรดเป็น SQL Server Standard ทีหลัง)

ขั้นตอนใน Prism Central:

  1. เข้า Prism Central → เมนู Compute & Storage → VMs → กด Create VM
  2. ถ้ายังไม่มี ISO ของ Ubuntu Server 24.04 ในระบบ ให้ไปที่ Settings → Image Configuration อัปโหลด ISO ก่อน แล้วค่อยกลับมา Create VM
  3. Name: attg-apphost-01
  4. vCPU(s): 1 socket × 4 core — Memory: 8 GiB
  5. Disk: Add New Disk → Type: SCSI → Size: 80 GiB → เลือก Storage Container ที่ IT กำหนด
  6. CD-ROM: แนบ ISO ของ Ubuntu Server ที่อัปโหลดไว้
  7. Network Adapter (NIC): เลือก VLAN/Subnet ที่ทีมเครือข่ายบอกไว้ (ข้อมูลจากกล่องด้านบน)
  8. กด Save แล้ว Power On เครื่อง จากนั้นเปิด Console เพื่อเริ่มติดตั้ง Ubuntu
  9. ระหว่างติดตั้ง Ubuntu: เลือกติดตั้ง OpenSSH Server ด้วย (มีตัวเลือกให้ติ๊กตอนถามเรื่อง Featured Server Snaps) — จำเป็นเพื่อจะได้ SSH เข้ามาทำขั้นตอนถัดไปจากเครื่องอื่นได้ ไม่ต้องเปิด Console ค้างไว้
  10. ตั้ง username/password สำหรับ login ตอนติดตั้ง แล้วรอจนติดตั้งเสร็จ + reboot
02

ตั้งค่า OS พื้นฐาน

SSH เข้าเครื่อง (จาก PuTTY หรือ Terminal) ด้วย IP ที่ Ubuntu แสดงตอนติดตั้งเสร็จ แล้วรันตามลำดับ:

bash
sudo apt update && sudo apt full-upgrade -y
sudo timedatectl set-timezone Asia/Bangkok
sudo hostnamectl set-hostname attg-apphost-01

ก่อนตั้ง Static IP ต้องรู้ชื่อการ์ดเครือข่ายก่อน (ไม่ใช่ทุกเครื่องชื่อ ens160 เหมือนกัน) รันคำสั่งนี้ดูชื่อจริง:

bash
ip a

มองหาชื่อการ์ดที่ไม่ใช่ lo (เช่น ens160, eth0, enp0s3) — ใช้ชื่อนั้นแทนในไฟล์ด้านล่าง

แก้ไฟล์ /etc/netplan/00-installer-config.yaml (เปิดด้วย sudo nano /etc/netplan/00-installer-config.yaml) แล้วแทนที่ค่าทั้งหมดด้วยข้อมูลจริงที่ขอจากทีมเครือข่ายไว้ในขั้นตอนแรก:

yaml — ตัวอย่าง
network:
  version: 2
  ethernets:
    ens160:                      # ← เปลี่ยนเป็นชื่อจริงจาก `ip a`
      addresses: [10.20.5.50/24]  # ← IP ที่ Network ตั้งให้ + subnet (/24 = 255.255.255.0)
      routes:
        - to: default
          via: 10.20.5.1          # ← Default Gateway ที่ Network ให้มา
      nameservers:
        addresses: [10.20.0.10, 10.20.0.11]  # ← DNS Server ภายในบริษัท

ตัวเลข IP ในตัวอย่างเป็นแค่ตัวอย่างเฉยๆ ต้องเปลี่ยนเป็นเลขจริงที่ทีมเครือข่ายให้มาทั้งหมด

bash
sudo netplan apply
ip a   # เช็คว่า IP ใหม่ขึ้นแล้ว
ping -c 3 10.20.5.1   # ทดสอบ ping หา gateway ให้แน่ใจว่าต่อเน็ตได้

เมื่อ IP ใหม่ใช้งานได้แล้ว ให้ reboot อีกครั้งให้ชื่อเครื่องใหม่มีผลเต็มที่:

bash
sudo reboot

หลัง reboot ให้ SSH เข้าใหม่โดยใช้ Static IP ตัวใหม่ แทน IP เดิม

03

ติดตั้ง Docker

ใช้สคริปต์ติดตั้งอย่างเป็นทางการของ Docker (ครอบคลุม Docker Engine + Compose ในตัว ไม่ต้องติดตั้งแยก):

bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
newgrp docker

ตรวจว่าติดตั้งสำเร็จ — ควรเห็นเลขเวอร์ชันแบบนี้:

bash
docker --version
# Docker version 27.x.x, build xxxxxxx

docker compose version
# Docker Compose version v2.x.x

ทดสอบว่า Docker รันคอนเทนเนอร์ได้จริง (ไม่ใช่แค่ติดตั้งอย่างเดียว):

bash
docker run hello-world

ถ้าเห็นข้อความ "Hello from Docker!" แปลว่า Docker ทำงานสมบูรณ์ 100% พร้อมไปขั้นตอนถัดไป

04

ตั้ง SQL Express + โฟลเดอร์แอป

สร้างโฟลเดอร์กลางเก็บทุกแอป แล้ววาง docker-compose.yml สำหรับฐานข้อมูล:

bash
sudo mkdir -p /opt/attg-apps
cd /opt/attg-apps

สร้างไฟล์ docker-compose.yml:

docker-compose.yml
services:
  sql-express:
    image: mcr.microsoft.com/mssql/server:2022-latest
    container_name: attg-sql-express
    environment:
      ACCEPT_EULA: "Y"
      MSSQL_PID: "Express"
      SA_PASSWORD: "<ตั้งรหัสผ่านที่ปลอดภัย>"
    ports:
      - "1433:1433"
    volumes:
      - sql-data:/var/opt/mssql
    restart: unless-stopped

volumes:
  sql-data:
!
รหัสผ่าน SA ต้องมีตัวใหญ่+เล็ก+ตัวเลข+สัญลักษณ์ อย่างน้อย 8 ตัว ไม่งั้นคอนเทนเนอร์จะไม่ยอมสตาร์ท เก็บรหัสนี้ไว้ส่งให้ทีมแอปในขั้นตอนที่ 07 (ห้ามใช้รหัสผ่านง่ายๆ เพราะเป็นบัญชีสิทธิ์สูงสุดของฐานข้อมูล)

แต่ละบรรทัดในไฟล์หมายถึงอะไร:

บรรทัดความหมาย
imageเวอร์ชัน SQL Server ที่ Microsoft ปล่อยอย่างเป็นทางการ (ล็อกเวอร์ชันไว้ ไม่สุ่มดึงตัวใหม่เอง)
ACCEPT_EULAยอมรับเงื่อนไขการใช้งานของ Microsoft (ต้องเป็น "Y" ไม่งั้นรันไม่ได้)
MSSQL_PIDเลือกรุ่นฟรี (Express) — ถ้าไม่ใส่จะไปใช้รุ่น Developer โดย default
portsเปิดพอร์ต 1433 (พอร์ตมาตรฐานของ SQL Server) ให้แอปอื่นต่อเข้ามาได้
volumesเก็บข้อมูลฐานข้อมูลไว้นอกคอนเทนเนอร์ — ถ้าลบ/สร้างคอนเทนเนอร์ใหม่ ข้อมูลจะไม่หาย
restartถ้าเครื่อง Server รีสตาร์ท คอนเทนเนอร์นี้จะเปิดขึ้นมาเองอัตโนมัติ

สั่งรัน:

bash
docker compose up -d
docker ps

ผลลัพธ์ docker ps ที่ถูกต้องควรมีลักษณะนี้ (สถานะเป็น "Up"):

output ตัวอย่าง
CONTAINER ID   IMAGE                              STATUS         PORTS
a1b2c3d4e5f6   mcr.microsoft.com/mssql/server...  Up 2 minutes   0.0.0.0:1433->1433/tcp

ถ้า STATUS ขึ้น "Restarting" ซ้ำๆ แปลว่ารหัสผ่าน SA ไม่ผ่านเงื่อนไขความปลอดภัย — กลับไปแก้ในไฟล์แล้วรัน docker compose up -d ใหม่

แอปแต่ละตัว (เช่น ATTG ACM) จะมี service เพิ่มเข้ามาในไฟล์นี้ทีหลัง — ทีมแอปจะส่งไฟล์ที่อัปเดตแล้วมาให้รัน docker compose up -d ซ้ำอีกครั้งตอนติดตั้งแอปจริง

05

เครือข่ายและ Firewall

เปิดพอร์ตเฉพาะจากวง IP ภายในของกลุ่ม ATTG เท่านั้น (แก้ 10.x.0.0/16 เป็นวง IP จริงของบริษัท):

bash
sudo ufw allow from 10.x.0.0/16 to any port 1433 proto tcp
sudo ufw allow from 10.x.0.0/16 to any port 80,443 proto tcp
sudo ufw enable

พอร์ต 1433 = ฐานข้อมูล, พอร์ต 80/443 = สำหรับหน้าเว็บแอปที่จะติดตั้งภายหลัง ไม่ต้องเปิดออกอินเทอร์เน็ตเลย เพราะใช้แค่ภายในเครือข่าย ATTG

06

ตรวจสอบว่าใช้งานได้

เช็คว่า container ฐานข้อมูลรันอยู่และตอบสนอง:

bash
docker exec -it attg-sql-express /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U sa -P '<รหัสผ่านที่ตั้งไว้>' -C \
  -Q "SELECT @@VERSION"

ถ้าเห็นข้อความเวอร์ชัน SQL Server ตอบกลับมา แปลว่าฐานข้อมูลพร้อมใช้งานแล้ว
